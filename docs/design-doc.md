# Dungeon Escape — Design Doc

Дипломный проект курса «Разработчик игр» (XYZ School). C++, SFML 2.5.1.
Рабочее название проекта в коде и репозитории — Rogalique.
Направление диплома: **Graphics Developer**, выполнен средний уровень.

## 1. Общее описание

- **Жанр:** roguelike с процедурным подземельем, вид сверху, движение по клеткам.
- **Сюжет:** героя похитили, он очнулся в подземелье и пытается из него сбежать.
- **Цель игрока:** пройти как можно больше уровней подряд. На каждом уровне нужно
  найти дверь-выход, не попавшись врагу.
- **Герой:** зелёный квадрат, ходит по клеткам клавишами WASD, у него 100 HP.
- **Враги** — два вида, оба бьют раз в 0.8 с, пока стоят на клетке игрока:
  - **шатун** (серый квадрат): видит игрока по прямой под любым углом, если на линии
    нет стен; увидел — идёт к нему, не видит — стоит. Медленный (шаг 0.3 с), урон 20 HP;
  - **ищейка** (фиолетовый квадрат): всегда знает, где игрок, и идёт к нему по
    кратчайшему пути. Быстрая (шаг 0.15 с), урон 25 HP.
- **Расписание по уровням:** шатунов 1 → 2 (2 ур.) → 3 (4 ур.) → 4 (5 ур.) → 5 (с 8 ур.);
  ищейка появляется на 10 уровне, вторая — на 15. Зелий нет до 4 уровня, с 4 — одно, с 8 — два.
- **Что делать:** уходить от врагов, подбирать зелья (+20 HP), искать дверь (чёрная клетка).
  Встал на дверь — следующий уровень. HP кончилось — Game Over и счёт пройденных уровней,
  рестарт по пробелу.

## 2. Механики и фичи

### Было в начале диплома (база, первый коммит)

- Процедурная генерация уровня: комнаты без пересечений и коридоры между ними (`Dungeon`).
- Движение игрока по сетке с кулдауном 0.1 с.
- Враг с простым («жадным») преследованием, кулдаун 0.15 с.
- Спавн игрока и врага в случайных комнатах, враг не ближе 10 клеток.
- Камера следует за игроком.

### Добавил сам за время диплома

| Фича | Что делает |
|---|---|
| Чистка кода | убран мёртвый код, лишние проверки, единый стиль имён |
| Дверь и переход на уровень | касание двери → мир замирает на 3 с → ступенчатое затемнение → новый уровень под чёрным экраном → осветление |
| Тряска камеры | **Graphics, лёгкий уровень.** Пока враг на клетке игрока, камера дрожит на ±10 px; у края карты сдвиг отражается |
| Камера в границах мира | камера не показывает черноту за картой; по периметру карты всегда стена |
| Враг на BFS | вместо жадного поиска — волна от игрока по карте расстояний; враг больше не застревает и не ходит маятником |
| Здоровье и Game Over | 100 HP, урон с паузой между ударами, медленное затемнение, экран смерти со счётом, рестарт |
| HUD | панель сверху: HP и номер уровня, мир рисуется только под ней |
| Зелья здоровья | +20 HP до потолка 100, количество зависит от номера уровня |
| Система частиц | **Graphics, средний уровень.** Класс `Particle`, вспышка из 12 частиц: красные искры при ударе, зелёные при зелье; через 0.6 с частицы исчезают и удаляются |
| Release-сборка | exe со статически подключённым SFML, запускается без VS |
| Чистка кода 2 | единый стиль имён, мёртвый код, неверные комментарии, константа `MAX_HP_PLAYER`, текст экрана смерти, чистота репозитория |
| Виды врагов | наследование: `Enemy` — абстрактный базовый класс (виртуальный `FindPlayer`, виртуальный деструктор), наследники `EnemyHound` (BFS) и `EnemyShatun` (взгляд по прямой); враги в `std::vector<std::unique_ptr<Enemy>>`, свой таймер шага и урон у каждого вида, расписание по уровням; враги не появляются в стенах, на игроке, двери и друг на друге, не наступают на дверь и друг на друга |

## 3. Оценка фич в сторипоинтах

Шкала: 1 — мелкая правка, 2 — простая задача, 3 — небольшая фича, 5 — фича с новой
логикой, 8 — фича с новой для меня теорией.

| Фича | SP | Почему так |
|---|---|---|
| Чистка кода | 2 | правки в знакомом коде |
| Дверь и переход на уровень | 8 | новое: перегенерация мира, таймеры фаз, затемнение через альфа-канал |
| Тряска камеры | 2 | случайный сдвиг центра камеры |
| Камера в границах мира | 3 | зажим через min/max, тряска с отражением от края |
| Враг на BFS | 8 | новый алгоритм: очередь, карта расстояний, спуск по склону |
| Здоровье, Game Over, HUD | 5 | несколько состояний игры, отдельная камера под HUD |
| Зелья здоровья | 3 | новый класс, спавн с проверками, удаление из вектора |
| Система частиц | 5 | новый класс, жизненный цикл в векторе, движение в пикселях |
| README, Release, Design Doc | 3 | документация и сборка |
| Чистка кода 2 | 3 | правки по списку в знакомом коде, чистка репозитория |
| Виды врагов (шатун) | 8 | новая теория: наследование, виртуальные функции, `unique_ptr`; взгляд по прямой |

## 5. Работа с Git

Правило: одна фича — одна ветка от свежего `main`, затем Pull Request с описанием и merge.
Префиксы веток: `feature/` — новая механика, `fix/` — исправление и чистка,
`docs/` — документация.

| PR | Ветка | Зачем |
|---|---|---|
| #1 | `fix/cleanup` | привести базовый код в порядок перед новыми фичами |
| #2 | `feature/take-new-lvl` | дверь, переходы между уровнями, тряска камеры |
| #3 | `feature/camera-clamp` | камера не выходит за карту |
| #4 | `feature/enemy-unstuck` | враг на BFS вместо застревающего жадного поиска |
| #5 | `feature/health` | здоровье, Game Over, рестарт, HUD |
| #6 | `feature/potion` | зелья здоровья |
