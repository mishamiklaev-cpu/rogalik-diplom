# Dungeon Escape — Design Doc

Дипломный проект курса «Разработчик игр» (XYZ School). C++, SFML 2.5.1.
Рабочее название проекта в коде и репозитории — Rogalique.
Направление диплома: **Graphics Developer**, выполнен средний уровень.

## 1. Общее описание

- **Жанр:** roguelike с процедурным подземельем, вид сверху, движение по клеткам.
- **Сюжет:** героя похитили, он очнулся в подземелье и пытается из него сбежать.
- **Цель игрока:** пройти как можно больше уровней подряд. На каждом уровне нужно
  найти дверь-выход, не попавшись врагу.
- **Герой:** рыжий парень в синей рубахе, бегает по клеткам стрелками и смотрит
  туда, куда бежит. У него 100 HP.
- **Враги** — два вида, оба бьют раз в 0.8 с, пока стоят на клетке игрока:
  - **шатун** (большой зелёный зомби с топором): видит игрока по прямой под любым углом,
    если на линии нет стен; увидел — идёт к нему, не видит — стоит. Медленный (шаг 0.3 с),
    урон 20 HP;
  - **ищейка** (мёртвый пёс): всегда знает, где игрок, и бежит к нему по кратчайшему пути.
    Шатунов обегает, а в узком коридоре ждёт, пока шатун не уйдёт: это передышка для игрока.
    Быстрая (шаг 0.15 с), урон 25 HP.
- **Расписание по уровням:** шатунов 1 → 2 (2 ур.) → 3 (4 ур.) → 4 (5 ур.) → 5 (с 8 ур.);
  ищейка появляется на 10 уровне, вторая — на 15. Зелий нет до 4 уровня, с 4 — одно, с 8 — два.
- **Что делать:** уходить от врагов, подбирать зелья (+20 HP), искать дверь (деревянная, в каменной рамке).
  Встал на дверь — следующий уровень. HP кончилось — Game Over, счёт пройденных уровней,
  ввод имени для таблицы рекордов (можно пропустить) и мини-меню: новая игра или главное меню.
- **Меню:** игра открывается в главном меню (Start, Records, Options, Exit).
  Esc в игре — пауза с мини-меню: продолжить, новая игра, главное меню.

## 2. Механики и фичи

### Было в начале диплома (база, первый коммит)

- Процедурная генерация уровня: комнаты без пересечений и коридоры между ними (`Dungeon`).
- Движение игрока по сетке с кулдауном 0.1 с.
- Враг с простым («жадным») преследованием, кулдаун 0.15 с.
- Спавн игрока и врага в случайных комнатах, враг не ближе 10 клеток.
- Камера следует за игроком.

### Добавил сам за время диплома

| Фича | Что делает |
|---|---|
| Чистка кода | убран мёртвый код, лишние проверки, единый стиль имён |
| Дверь и переход на уровень | касание двери → мир замирает на 1 с → ступенчатое затемнение → новый уровень под чёрным экраном → осветление |
| Тряска камеры | **Graphics, лёгкий уровень.** Пока враг на клетке игрока, камера дрожит на ±10 px; у края карты сдвиг отражается |
| Камера в границах мира | камера не показывает черноту за картой; по периметру карты всегда стена |
| Враг на BFS | вместо жадного поиска — волна от игрока по карте расстояний; враг больше не застревает и не ходит маятником |
| Здоровье и Game Over | 100 HP, урон с паузой между ударами, медленное затемнение, экран смерти со счётом, рестарт |
| HUD | панель сверху: HP и номер уровня, мир рисуется только под ней |
| Зелья здоровья | +20 HP до потолка 100, количество зависит от номера уровня |
| Система частиц | **Graphics, средний уровень.** Класс `Particle`, вспышка из 12 частиц: красные искры при ударе, зелёные при зелье; через 0.6 с частицы исчезают и удаляются |
| Release-сборка | exe со статически подключённым SFML, запускается без VS |
| Чистка кода 2 | единый стиль имён, мёртвый код, неверные комментарии, константа `MAX_HP_PLAYER`, текст экрана смерти, чистота репозитория |
| Виды врагов | наследование: `Enemy` — абстрактный базовый класс (виртуальный `FindPlayer`, виртуальный деструктор), наследники `EnemyHound` (BFS) и `EnemyShatun` (взгляд по прямой); враги в `std::vector<std::unique_ptr<Enemy>>`, свой таймер шага и урон у каждого вида, расписание по уровням; враги не появляются в стенах, на игроке, двери и друг на друге, не наступают на дверь и друг на друга; в волне ищейки шатуны считаются препятствием |
| Текстуры | класс `GameTextures` загружает картинки один раз при старте; стена, пол, дверь, зелье, герой и враги рисуются текстурами `Resources/Textures/`; картинка стены растянута на 2×2 клетки через `setTextureRect`; если файла нет, элемент рисуется прежним цветом |
| Анимация и направления | спрайт-листы: 2 кадра на 4 направления; `enum class Direction` выбирает ряд, номер кадра — столбец; кадр меняется только при реальном шаге; картинку врага выбирает виртуальная `GetTextureEnemy` |
| Меню и пауза | `enum class GameState` (Menu, Playing, Paused): игровая логика идёт только в Playing, часы и рисование работают всегда; главное меню с картинкой, мини-меню паузы и экрана смерти, подтверждение выхода и новой игры; выбор стрелками и Enter через события `KeyPressed`; один общий сброс мира для новой игры и выхода в меню; подсказка управления на панели |
| Звук | класс `GameSounds`: `sf::Music` для зацикленной музыки меню и игры (ставится на паузу вместе с игрой), `sf::SoundBuffer` + `sf::Sound` для эффектов клика, выбора, двери, зелья, урона и конца игры |
| Таблица рекордов | ввод имени на экране смерти через событие `TextEntered` (Esc — пропуск), 10 лучших результатов в отсортированном векторе, сохранение в `records.txt` через `ifstream` и `ofstream`, экран Records |
| Опции | экран Options: включение и выключение музыки и звуков через громкость |

## 5. Работа с Git

Правило: одна фича — одна ветка от свежего `main`, затем Pull Request с описанием и merge.
Префиксы веток: `feature/` — новая механика, `fix/` — исправление и чистка,
`docs/` — документация.

| PR | Ветка | Зачем |
